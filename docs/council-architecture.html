02

runtime mount points · agent-session.ts

Three mount points in execution order: gates run before the extension runner, the state card is regenerated before each conversation round, and the tool surface is registered once and available process-wide.

:680
labBeforeToolCheck — tool-call gate

Runs before the extension runner and intercepts violations: cross-line writes, ledger writes without holding the lock, illegal state transitions. The council layer's completion gate adds a new branch here (see 05).

:1814
transformContext — state-card injection

Regenerates the state card before every conversation round, anomalies first: breaker-tripped lines, mismatches, workers awaiting collection and open claims lead; normal state is folded into a single background line. Rebuilt every round, it naturally resists context compression.

:3724
createLabToolDefinitions — register lab_* tools

Registers all lab_* tool definitions once; the process-wide visible tool surface is decided here, and the council's new lab_council_post and lab_council_verdict hang in the same place.

04

gate checklist and multi-role precedent

completed is not a free state: it is released only when every machine-verifiable condition passes; multi-process collaboration already has precedent in the review subcommand.

completed gate checklist (labBeforeToolCheck)

  • metrics: at least one metric on the run; a run completed out of thin air is rejected
  • verified: a run with a registered eval_spec must pass re-verification; a mismatch blocks permanently
  • non-drift: when snapshot comparison detects environment drift, completion is refused
  • revise_reason: rewriting a metric of the same name must carry a revision reason; a missing reason is refused
  • breaker: while a line is paused, registration and dispatch are all refused; resume first, then execute
  • council approved: added once the council layer ships (see 05, fail-closed)

multi-role precedent · review subcommand

  • generator / critic / ranker three kinds of processes run concurrently, each in its own session
  • no shared conversation: processes exchange information only through the ledger and artifacts; one party's output is an invisible narrative to another
  • non-blocking: the three kinds of processes never wait for each other; the skill layer aggregates once all have finished
  • the council layer reuses this concurrency model, upgrading "one-shot review" to "multi-round adversarial review + adjudication"

Council

council convening — new skill subcommand council

The shared transcript lands in the ledger: new lab.db tables councils + council_messages. Each round cycles three role processes, each with an independent session, writing into the transcript through tools.

per-round loop
LAB_ROLE=executor executor process
the executing side, defending in person

Reports the evidence chain: metrics, verification results, artifact locations; responds point by point to the auditor's challenges.

──▶ lab_council_post ──▶ transcript
LAB_ROLE=auditor auditor process
independent cross-examination

Read-only over the ledger and artifacts; challenges item by item: does the evidence cover the conclusion, does verification reconcile, has the snapshot drifted.

──▶ lab_council_post ──▶ transcript
LAB_ROLE=chair chair process
adjudicator

Reads the transcript and ledger, synthesizes both sides' presentations into a verdict; at most one verdict per round.

──▶ lab_council_verdict ──▶ approved / rejected
shared transcript lab.db · councils lab.db · council_messages the three processes' independent sessions meet here; between processes the transcript is read-only
chair verdict → approved → released rejected → the run can never be marked completed (fixes allow a new council to be convened) expired (rounds exhausted) → likewise closes that run's completed channel
the verdict is written back to the ledger; the completion gate decides on it

Completion Gate

completion gate — new branch in labBeforeToolCheck, fail-closed

lab_update_run status=completed requires an approved council covering this run; when the condition is missing the call is refused, and refusal is the gate's default behavior.

query the councils table covers this run status = approved no approved → refuse

the auditor's sources of fact

The auditor's sources of fact are only three: the ledger, artifact files, and independent re-verification results; the executor's narrative serves solely as accusatory material — a narrative may point out the direction of a challenge, but whether the challenge holds must be verified against the three sources. This constraint is written into the auditor's discipline prefix, in the same line as the review precedent's "no shared conversation".

ledger · lab.db artifact files · artifacts + checksums independent re-verification · verify / snapshot executor narrative · accusatory material only

07

council state machine

One council record per convening; state transitions follow the chair's verdict. After rejected, fixing the issues allows a new convening, but the original run's completed channel stays closed until an approved exists.

State lands in the councils table; every council_message carries a round number and a role; the whole process is traceable in the activity table.
